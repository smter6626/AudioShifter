# AudioShifter macOS 行为规格

> 文档定位：本文件是 macOS 第一阶段的**用户可见行为合同**，用于把 `docs/macos_rebuild_static.md` 中的长期原则细化为可实现、可测试、无歧义的行为规则。
>
> 本文件不记录执行进度，不替代 `docs/macos_rebuild_runtime.md`；不描述具体类、函数或线程实现，模块职责见同目录 `architecture_plan.md`，测试映射见 `verification_matrix.md`。
>
> 规则来源优先级：用户明确确认的产品规则 > `docs/macos_rebuild_static.md` > 已验证的 macOS 环境能力 > Windows 历史实现。Windows 历史实现只用于识别旧版语义，不自动成为新版本合同。

## 1. 适用范围

本规格适用于 AudioShifter 的 macOS 第一阶段版本。

- 目标平台：Apple Silicon `arm64`。
- 主要用户：非技术用户。
- 主要界面语言：中文。
- 处理方式：完全本地处理，不上传音频。
- 同一时间只允许一个处理任务。
- 本阶段不包含账户、联网授权、机器码、激活码、注册机、授权文件校验或其他访问限制。
- 本阶段不承诺 Intel Mac、通用二进制、Developer ID 签名、Apple 公证或 Mac App Store 分发。

## 2. 合同编号说明

为方便实现和测试，每条稳定行为使用合同编号：

- `IN-*`：输入文件
- `PITCH-*`：变调参数
- `SPEED-*`：变速参数
- `PIPE-*`：音频处理管线
- `OUT-*`：输出文件
- `NAME-*`：文件命名与冲突
- `TEMP-*`：临时资源
- `TASK-*`：任务、取消与界面状态
- `ERR-*`：错误与诊断
- `PRIV-*`：隐私与安全
- `EXCL-*`：明确排除项

## 3. 输入文件合同

### IN-001：首阶段支持格式

首阶段只向用户承诺以下输入格式：

- MP3：`.mp3`
- M4A：`.m4a`
- WAV：`.wav`
- FLAC：`.flac`

扩展名匹配不区分大小写，例如 `.MP3`、`.M4A` 仍应接受。

### IN-002：不自动扩大格式承诺

即使当前 FFmpeg 可以读取其他格式，文件选择器、用户文档和测试合同也不得自动加入其他格式。新增格式必须经过单独确认和验证。

### IN-003：路径与文件状态

开始处理前，输入路径必须满足：

1. 路径存在。
2. 路径指向普通文件，而不是目录。
3. 当前进程可读取该文件。
4. 文件大小大于 0。
5. 扩展名属于首阶段支持列表。

### IN-004：真实媒体校验

扩展名通过不代表文件有效。FFmpeg 无法解码、文件损坏、内容与扩展名不符或文件不包含可处理音频流时，必须终止任务并归类为输入媒体错误。

### IN-005：路径字符

输入路径应支持 macOS 文件系统允许的常见字符，包括：

- 中文和其他 Unicode 字符
- 空格
- 括号
- 单引号
- `&`
- 多个点号

外部命令必须使用参数数组调用，不得把路径拼接进 Shell 命令字符串。

### IN-006：源文件保护

任何处理结果、错误、取消或清理操作都不得修改、重命名、移动或删除输入文件。验证时应通过处理前后哈希确认源文件不变。

## 4. 变调参数合同

### PITCH-001：参数含义

变调参数表示相对于原音频的半音变化量：

- `0`：保持原调
- 正整数：升调
- 负整数：降调

例如：

- `+3`：升高 3 个半音
- `-3`：降低 3 个半音

### PITCH-002：输入类型

变调只允许整数，不允许小数。

可接受的输入形式：

- `0`
- `3`
- `+3`
- `-3`

输入前后空白可以被去除。正整数无论是否显式输入 `+`，内部和文件名均规范化为显式正号。

以下输入必须拒绝：

- 空字符串
- 非数字文本
- `1.5`
- `NaN`
- `Infinity`
- 百分号或其他单位字符

### PITCH-003：范围

允许范围固定为：

```text
-24 ≤ pitch ≤ +24
```

上下界均可取。超出范围必须在启动外部进程前被拒绝。

### PITCH-004：文件名表示

文件名中的变调参数始终保留并显式带符号：

- `0` 写作 `+0`
- `3` 写作 `+3`
- `-3` 写作 `-3`

## 5. 变速参数合同

### SPEED-001：参数含义

用户输入的是**相对于原速度的变化百分比**，不是最终播放速度百分比。

- `0`：保持原速
- `+20`：加速 20%，最终速度为原速度的 120%
- `-20`：减速 20%，最终速度为原速度的 80%

用户不输入 `%`，百分号仅用于界面说明和输出文件名。

### SPEED-002：输入类型

变速值允许整数或有限小数。

可接受示例：

- `0`
- `+20`
- `-20`
- `+12.5`
- `-7.25`

非零值应使用 `+` 或 `-` 表达相对变化方向。输入前后空白可以被去除。

以下输入必须拒绝：

- 空字符串
- 非数字文本
- 带 `%` 的字符串
- `NaN`
- `Infinity`
- 只有符号而没有数字

`+0`、`-0` 和 `0` 均规范化为 `+0`。

### SPEED-003：范围

允许范围固定为：

```text
-95 ≤ speed_change ≤ +400
```

上下界均可取，对应最终速度范围为原速度的 5% 至 500%。超出范围必须在启动外部进程前被拒绝。

### SPEED-004：底层换算

传给 Rubber Band 的 tempo multiplier 为：

```text
tempo_ratio = 1 + speed_change / 100
```

示例：

| 用户输入 | `tempo_ratio` | 最终速度 | 理论输出时长比例 |
|---:|---:|---:|---:|
| `0` | `1.0` | 100% | `1.0` |
| `+20` | `1.2` | 120% | `1 / 1.2` |
| `-20` | `0.8` | 80% | `1 / 0.8` |
| `-95` | `0.05` | 5% | `20.0` |
| `+400` | `5.0` | 500% | `0.2` |

环境冒烟测试中的 `--tempo 0.9` 只证明换算语义可用，不是产品默认值。

### SPEED-005：文件名表示

文件名中的速度变化参数始终保留并显式带符号，数值规范如下：

- 零写作 `+0%`
- 正值写作 `+数值%`
- 负值写作 `-数值%`
- 小数统一使用 `.`
- 去除无意义的尾随零和末尾小数点

示例：

- `+20.0` → `+20%`
- `-7.500` → `-7.5%`
- `0` → `+0%`

## 6. 音频处理管线合同

### PIPE-001：固定处理阶段

第一阶段采用以下三阶段管线：

```text
输入文件
→ FFmpeg 解码和标准化
→ Rubber Band 变调与变速
→ FFmpeg 编码 MP3
```

三个阶段必须可以分别识别成功或失败，不能把全部错误合并为一个笼统结果。

### PIPE-002：中间音频规格

FFmpeg 解码后的工作音频固定为：

- WAV
- PCM signed 16-bit little-endian
- 44.1 kHz
- 双声道

该规格沿用旧版兼容基线，并已在 macOS 工具链中验证可用。

### PIPE-003：Rubber Band 语义

Rubber Band 同时处理变调和变速，并启用：

- 半音变调
- tempo multiplier
- R3/finer 精细引擎方向
- formant preservation 共振峰保持方向

`pitch = 0` 或 `speed_change = 0` 时，相应参数仍作为明确的零变化输入处理，不改变双参数合同。

### PIPE-004：输出编码规格

最终输出固定为：

- MP3
- `libmp3lame`
- 320 kbps
- 44.1 kHz
- 双声道

### PIPE-005：媒体有效性

处理成功必须至少满足：

1. 三个外部处理阶段均以成功状态结束。
2. 最终文件存在且大小大于 0。
3. FFprobe 可以读取最终文件。
4. 最终音频编码为 MP3。
5. 采样率为 44.1 kHz。
6. 声道数为 2。
7. 输出时长与速度换算方向一致。

具体时长误差阈值由测试实现阶段根据短音频和编码延迟确定，不在本合同中写入未经验证的固定数值。

### PIPE-006：元数据

第一阶段不复制、不承诺保留源文件的标题、艺术家、专辑、歌词、章节、封面图片或其他元数据。合同只保证音频内容可正常处理并生成可播放结果。

## 7. 输出位置合同

### OUT-001：默认输出目录

所有成功结果固定保存到当前用户的下载目录：

```text
~/Downloads/
```

不保存到输入文件所在目录，也不在每次处理时弹出“另存为”选择器。

### OUT-002：目录预检查

处理开始前必须确认下载目录：

1. 存在。
2. 是目录。
3. 当前进程具有写入权限。

任一条件不满足时，弹窗给出明确原因并终止任务，不自动切换到其他目录。

### OUT-003：空间不足

磁盘空间不足可能在预检查或处理过程中被发现。发现空间不足时必须：

- 终止任务。
- 显示“磁盘空间不足，无法保存到下载目录”等可理解提示。
- 不留下被误认为成功结果的残缺 MP3。
- 尽可能清理本次临时文件。

### OUT-004：成功提示

成功后必须向用户显示最终输出文件的完整路径。

## 8. 输出文件命名合同

### NAME-001：基础格式

输入文件名为 `name.ext`，变调参数为 `x`，速度变化参数为 `y` 时，基础输出名固定为：

```text
name<x><y>%.mp3
```

其中：

- `name` 为去除最后一个扩展名后的原文件名。
- `x` 为显式带符号的整数半音。
- `y` 为显式带符号的整数或规范化小数。
- `%` 由程序自动添加。
- 输出扩展名固定为 `.mp3`。

示例：

| 输入文件 | 变调 | 变速变化 | 输出文件 |
|---|---:|---:|---|
| `name.mp3` | `+3` | `+20` | `name+3+20%.mp3` |
| `name.wav` | `-3` | `-20` | `name-3-20%.mp3` |
| `name.flac` | `+3` | `-12.5` | `name+3-12.5%.mp3` |
| `name.m4a` | `-2` | `+30.25` | `name-2+30.25%.mp3` |
| `name.mp3` | `0` | `0` | `name+0+0%.mp3` |

### NAME-002：零值不省略

无论变调或变速是否为零，文件名都必须保留两个参数。不得生成只含一个参数或完全省略参数的结果名。

### NAME-003：不覆盖已有文件

程序永远不得覆盖下载目录中的已有文件，也不得删除已有文件。

FFmpeg 编码阶段不得依赖 `-y` 静默覆盖最终输出路径。

### NAME-004：自动递增

若基础输出路径已存在，程序选择第一个不存在的递增名称：

```text
name+3+20%.mp3
name+3+20%_2.mp3
name+3+20%_3.mp3
...
```

后缀从 `_2` 开始，放在 `.mp3` 之前。

### NAME-005：冲突提示

当基础名称已存在并采用递增名称时，必须弹窗提示：

- 原目标文件已存在。
- 已有文件不会被覆盖。
- 本次将使用的实际新文件名或完整路径。

用户确认提示后任务继续，无需让用户手工修改名称。

### NAME-006：竞态保护

即使同一应用禁止并发任务，仍可能有外部程序在处理期间创建同名文件。因此在最终编码前必须再次确认目标路径未被占用；若发生新冲突，应重新分配安全递增名称或以明确的输出冲突错误终止，绝不能覆盖。

## 9. 临时资源合同

### TEMP-001：独立工作区

每次任务必须在 macOS 系统临时目录下创建独立、唯一的工作目录。不得使用固定全局文件名。

工作目录可包含：

- 解码后的 WAV
- Rubber Band 处理后的 WAV
- 其他仅属于本次任务的短期文件

### TEMP-002：禁止位置

临时文件不得写入：

- `~/Downloads/`
- 输入文件所在目录
- 仓库目录
- 固定的跨任务共享路径

### TEMP-003：清理时机

以下情况下均应尽可能清理本次临时工作区：

- 成功
- 输入解码失败
- Rubber Band 处理失败
- MP3 编码失败
- 用户取消
- 应用确认取消并退出

### TEMP-004：清理警告

若最终 MP3 已成功生成，但临时资源清理失败：

- 处理结果仍视为成功。
- 用户可收到简洁警告。
- 内部诊断记录残留路径和异常。
- 不得删除成功结果来掩盖清理失败。

## 10. 任务与取消合同

### TASK-001：禁止并发

同一应用实例同一时间只允许一个音频处理任务。

任务运行期间：

- 禁用“开始处理”。
- 不允许通过重复点击创建第二个任务。
- 输入控件是否锁定可由 GUI 实现决定，但提交给处理层的请求参数必须不可变。

### TASK-002：后台执行

外部音频处理不得阻塞 Tkinter 主线程。界面应保持可响应。

### TASK-003：取消按钮

任务运行期间提供“取消”操作。取消必须：

1. 标记任务进入取消流程。
2. 终止当前 FFmpeg 或 Rubber Band 子进程及由其启动的相关进程。
3. 不再启动后续处理阶段。
4. 清理临时工作区。
5. 删除不完整的最终输出文件。
6. 将界面恢复到可再次处理的状态。

取消不是错误，不应显示为“处理失败”。

### TASK-004：关闭窗口

用户在任务运行期间关闭应用时，必须询问是否取消当前任务并退出。

- 用户选择继续处理：关闭操作取消，任务继续。
- 用户确认退出：执行取消流程，清理后退出。
- 不得直接遗留后台子进程。

### TASK-005：状态阶段

用户可见状态至少区分：

- 就绪
- 正在检查
- 正在解码
- 正在变调/变速
- 正在生成 MP3
- 正在取消
- 完成
- 已取消
- 失败

## 11. 错误与诊断合同

### ERR-001：稳定错误类别

实现应使用稳定错误类别，而不是把底层异常文本直接当作唯一错误接口。

| 错误码 | 用户提示方向 | 内部证据 |
|---|---|---|
| `INPUT_NOT_FOUND` | 找不到所选文件 | 输入路径、OS 错误 |
| `INPUT_NOT_FILE` | 选择的路径不是文件 | 输入路径 |
| `INPUT_NOT_READABLE` | 文件无法读取 | 权限与 OS 错误 |
| `UNSUPPORTED_INPUT` | 首阶段不支持该格式 | 扩展名 |
| `INVALID_INPUT_MEDIA` | 文件损坏或不是有效音频 | FFmpeg 返回码和 stderr |
| `INVALID_PITCH` | 变调必须是 -24 到 +24 的整数 | 原始输入 |
| `INVALID_SPEED` | 变速必须是 -95 到 +400 的有效数值 | 原始输入 |
| `DOWNLOADS_NOT_FOUND` | 下载目录不存在 | 目标路径 |
| `DOWNLOADS_NOT_DIRECTORY` | 下载路径不是目录 | 目标路径 |
| `OUTPUT_PERMISSION_DENIED` | 无权写入下载目录 | OS 错误 |
| `DISK_FULL` | 磁盘空间不足 | errno、工具 stderr、路径 |
| `DEPENDENCY_MISSING` | 应用内部组件缺失 | 组件名和解析路径 |
| `DEPENDENCY_NOT_EXECUTABLE` | 音频组件无法启动 | OS 错误 |
| `DECODE_FAILED` | 无法读取或标准化源音频 | FFmpeg 命令、返回码、stderr |
| `PROCESS_FAILED` | 变调或变速处理失败 | Rubber Band 命令、返回码、stderr |
| `ENCODE_FAILED` | 无法生成 MP3 | FFmpeg 命令、返回码、stderr |
| `OUTPUT_NAME_CONFLICT` | 无法安全分配输出名称 | 所有候选路径 |
| `CANCELLED` | 处理已取消 | 取消阶段和子进程状态 |
| `CLEANUP_WARNING` | 结果已生成，但临时文件清理异常 | 残留路径和异常 |
| `UNKNOWN_ERROR` | 出现未预期错误 | traceback，仅内部使用 |

### ERR-002：用户提示

用户提示必须：

- 使用中文。
- 说明发生了什么。
- 说明用户可以采取的动作。
- 对路径相关错误显示必要路径。
- 不只显示返回码、异常类名或“处理失败”。

### ERR-003：内部诊断

内部诊断至少可以保留：

- 处理阶段
- 安全的命令参数数组
- 外部程序路径
- 返回码
- stdout/stderr 摘要
- 输入和输出路径
- 原始异常类型
- 清理结果

不得把用户音频内容写入日志。

### ERR-004：残缺输出

任何失败或取消流程都不得保留被误认为成功结果的残缺 MP3。只有通过最终有效性检查的文件才能作为成功结果保留。

## 12. 隐私与安全合同

### PRIV-001：本地处理

所有音频处理在本机完成，不上传文件，不要求网络连接、账户或远程授权。

### PRIV-002：无遥测

第一阶段不采集使用数据、音频信息、文件列表或遥测。

### PRIV-003：安全执行

外部程序调用必须使用参数数组，不经过 `shell=True`，不执行由用户输入拼接出的任意 Shell 字符串。

### PRIV-004：路径日志

若内部诊断记录本地路径，应明确日志只保存在本机，并避免无必要地长期保存完整路径。

## 13. 明确不继承的 Windows 历史行为

以下 Windows 历史行为明确不迁移：

- 机器码、激活码、注册机和 `license.dat`
- 固定在 Downloads 中使用共享临时 WAV 文件
- 使用 `-y` 静默覆盖已有输出
- 文件名中的速度值强制转换为整数
- 从工作线程直接更新 Tkinter 控件
- 只显示笼统异常文本
- 允许重复触发并行处理

## 14. 明确待后续验证但不改变本合同的项目

以下项目在实现和测试阶段验证，不代表当前合同缺失：

- 短音频编码延迟下的时长误差阈值
- 极限参数下的实际处理时间和音质
- 取消外部进程的最佳等待和强制终止时间
- 最低可运行 macOS 版本
- PyInstaller 打包后的依赖路径与纯 `arm64` 产物
- GPL 兼容分发或商业许可路线

这些事项不得在未验证前写成已满足的发布承诺。
